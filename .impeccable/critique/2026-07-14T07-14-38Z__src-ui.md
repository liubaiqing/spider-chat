## Anti-Patterns Verdict

**LLM assessment**：视觉层面不像 AI 拼装界面，整体安静、原生、功能导向。主要问题不是视觉，而是英文版本缺少一次完整的产品化校对，导致用户在关键节点失去信任。

**Deterministic scan**：`detect.mjs --json src/ui src/view.tsx src/settings.ts` 返回 0 个问题，没有规则命中或假阳性。

**Visual evidence**：在真实 Obsidian 中将 Spider 切换到 English 后，设置页立即变英文，但已打开的主界面保持中文；触发搜索重绘后主界面才变英文，而插件入口 tooltip 仍是“打开 spider”。浏览器 overlay 不适用，因为目标是 Obsidian Electron 插件，没有独立网页预览或可安全注入的浏览器 DOM。

## Overall Impression

Spider 的核心体验——选中文本、按 Tab、形成分支——很有辨识度，图谱与右侧聊天的结构也成熟。最大的机会是把“有英文字符串”升级为“完整可靠的英文产品”：默认、切换、弹窗、命令、帮助文档和术语必须形成同一套语言契约。

## What's Working

- 分支教学链路完整：引导卡片、选中文本锚点、自动生成追问草稿和创建成功通知共同强化核心操作。
- 上下文可见性好：路径、锚点、摘要、状态、搜索和笔记让深度探索不容易迷路。
- 样式尊重 Obsidian 主题变量，信息密度与留白控制合理；英文设置页未出现明显布局溢出。

## Priority Issues

### [P0] Tab/方向键/Delete 破坏键盘可访问性

**Why it matters**：视图级键盘监听在排除 `select`、`button`、链接等控件前就拦截 Tab；方向键和 Delete 也可能在非输入控件聚焦时触发图谱操作。键盘用户无法可靠遍历设置和操作区。

**Fix**：仅在画布获得焦点，或 AI 回复中存在选中文本时启用分支快捷键；统一排除 `input, textarea, select, button, a, [contenteditable], [role=button]`；Delete 只在画布节点上下文生效。

**Suggested command**：`$impeccable harden`

### [P1] 英文切换不是原子操作，且首次用户默认进入中文

**Why it matters**：代码默认 `zh-CN`，README 却写 English；实际测试中设置页先变英文，主界面要等下一次 React 状态变化才更新，命令与 ribbon tooltip 仍保留启动时语言。`confirmDelete()` 也固定输出中文。

**Fix**：首次安装跟随 Obsidian locale，无法识别时默认 English；引入全局 language-change 事件/可订阅设置状态；所有字符串和确认弹窗进入 i18n；命令显示名需要重载或明确提示用户 reload；系统默认标题使用语言无关 sentinel。

**Suggested command**：`$impeccable harden`

### [P1] API 配置被设计成失败后的补救，而不是首次使用步骤

**Why it matters**：没有 key/model 时 Send 仍可点击，用户提交问题后才得到错误；设置页的 “Test API” 描述还重复了 Model 的说明，不能解释测试会验证什么。

**Fix**：在空状态显示 “Connect an AI provider” 和 “Open Spider settings”；配置不完整时禁用 Send 但保留草稿；给常见供应商预设；将测试说明改为 “Verify the endpoint, API key, and model.”

**Suggested command**：`$impeccable onboard`

### [P1] 英文 README 会削弱安装前信任

**Why it matters**：英文 README 使用中文截图，保留“以后放 GIF”的内部 TODO，Community Store 安装步骤与 awaiting review 状态冲突，English 默认值与代码冲突，导出“固定中文”的描述也与英文导出实现冲突，最低 Obsidian 版本和 manifest 不一致。

**Fix**：做一次 release-truth audit；加入当前英文界面截图或 5 秒分支 GIF；未上架前把源码/BRAT 安装放在前面；所有版本、默认值、导出行为与代码保持一致。

**Suggested command**：`$impeccable clarify`

### [P2] 英文术语与语法仍像开发者内部模型

**Why it matters**：真实英文界面出现小写 `open`、`user`、`assistant`，并可能显示 `1 nodes`；“Ask this node”“New child”“Parent”不够自然，也削弱“研究工具”定位。

**Fix**：增加 plural rules；统一使用 “Open / You / AI”；将主要动作改为 “Branch” 或 “Create branch”、“Go to parent”、“Ask a question in this branch”；产品名统一写作 Spider。

**Suggested command**：`$impeccable clarify`

## Persona Red Flags

- **Alex（熟练用户）**：快捷键本应提升效率，但会抢占标准 Tab/方向键操作；Full map context 缺少 token 预算提示。
- **Jordan（首次英文用户）**：首次进入中文、API base URL/model 术语缺乏引导、错误后没有直达设置按钮。
- **Sam（键盘/无障碍用户）**：Tab 无法可靠移动焦点，部分输入仅靠 placeholder，部分点击目标较小。

## Cognitive Load

整体为中等负荷：主任务和结构清楚，分支引导、路径与反馈表现好；主要额外负荷来自 API 配置术语、语言切换后的混合状态，以及 Child/Parent/Anchor 等内部模型词汇。

## Minor Observations

- TypeScript 的字典类型保证了 key 完整性，是很好的基础。
- 英文设置页总体能正常换行，没有明显溢出；主界面搜索 placeholder 在窄区域会被截断，但不影响操作。
- 搜索功能已经实现，README Roadmap 仍写“Full-text node search”，需要更新。
- 英文 README 的中文截图与当前组件不一致，应优先替换。

## Questions to Consider

- Tab 在“没有选中文本”时创建空子节点，是否值得牺牲标准焦点导航？
- 默认标题是用户数据还是界面文案？如果是界面文案，不应把本地化结果永久写入地图数据。
- 导出语言应该跟随当前 UI、地图创建语言，还是在导出时单独选择？
